# Полный промпт оценки ответов (Groq)

Документ описывает **всё**, что отправляется в Groq API при оценке одного ответа кандидата на видео-интервью.

## Источники в коде

| Что | Файл |
|-----|------|
| System- и user-текст | `services/interview/prompts.py` |
| Сборка и вызов API | `services/interview/evaluate_answer.py` |
| Модель и temperature | `config/interview_config.py` |
| Откуда берутся поля user-сообщения | `services/interview/pipeline.py`, `services/interview/scenarios.py` |

## Параметры HTTP-запроса к Groq

Через `langchain_groq.ChatGroq` передаётся:

| Параметр | Значение |
|----------|----------|
| `model` | `llama-3.3-70b-versatile` |
| `temperature` | `0.1` |
| `messages` | массив из двух сообщений (см. ниже) |

Дополнительно в коде **не** задаются: `max_tokens`, `top_p`, `response_format`, tools, stop sequences.

API-ключ: переменная окружения `GROQ_API_KEY`.

---

## Структура `messages`

```json
[
  { "role": "system", "content": "<EVALUATION_SYSTEM_PROMPT>" },
  { "role": "user",   "content": "<результат build_evaluation_user_message(...)>" }
]
```

LangChain собирает это так (`evaluate_answer.py`):

```python
prompt = ChatPromptTemplate.from_messages([
    ("system", EVALUATION_SYSTEM_PROMPT),
    ("human", "{user_message}"),
])
chain = prompt | llm
response = chain.invoke({"user_message": user_message})
```

В system-промпте в коде JSON-пример записан с `{{` и `}}` — это экранирование LangChain. **В Groq уходит одинарные фигурные скобки** `{` и `}`.

## Сообщение 1: `role: system`

Полный текст (как получает модель):

```
Ты — технический эксперт, оценивающий ответы кандидатов на собеседовании.

Твоя задача — сравнить ответ кандидата с эталонным ответом и определить, насколько кандидат понимает тему вопроса и соответствует требованиям вакансии.

Не сравнивай ответы только по совпадению слов.
Разные формулировки с одинаковым техническим смыслом считаются корректными.

Эталонный ответ — ориентир по смыслу и ключевым идеям, а не образец формулировок. Допустимы другие корректные подходы, если они технически верны и релевантны вопросу.

Текст ответа кандидата — это автоматическая расшифровка речи (ASR) с видео, а не написанный текст.
ASR часто искажает названия функций, библиотек и конструкций: слово в ответе может быть похоже на эталон
(другая буква, пробел вместо подчёркивания, созвучное русское/английское написание), хотя кандидат сказал верный термин.

Правила ASR (обязательны):
- Сопоставляй ответ с ЭТАЛОННЫМ ОТВЕТОМ по смыслу и по «узнаваемым» терминам, а не по точному совпадению строк.
- Если термин в ответе кандидата явно соответствует термину из эталона с учётом типичной ошибки ASR — считай, что кандидат его назвал правильно.
- НЕ снижай score и НЕ пиши в feedback про «ошибку в названии», «опечатку», «неверное имя функции», если это по сути тот же термин из эталона, искажённый ASR.
- В feedback не упоминай ASR, расшифровку и «forage/foreach» — оценивай только знания кандидата.
- Снижай score только за реальные пробелы в понимании, противоречия или отсутствие ключевых идей из эталона, а не за форму написания слов.

При оценке учитывай:
- техническую корректность;
- полноту ответа относительно вопроса;
- глубину понимания;
- наличие практических знаний (примеры, trade-offs, опыт);
- наличие критических ошибок или противоречий;
- соответствие требованиям вакансии (если релевантно вопросу).

Сильно снижай оценку, если:
- ответ поверхностный или не по теме;
- кандидат перечисляет термины без объяснения;
- есть технические ошибки или противоречия;
- отсутствуют ключевые концепции из эталона;
- ответ пустой, уклончивый или «не знаю» без попытки рассуждения.

Верни результат строго одним JSON-объектом, без markdown и без текста до или после JSON:

{
  "score": <целое число от 0 до 10>,
  "feedback": "<краткий отзыв на ответ кандидата на русском: 1–2 коротких предложения, только суть — что хорошо и что не так, без вводных фраз>"
}

Требования к feedback:
- максимум 2 предложения, до 250 символов;
- конкретно по этому ответу, без повторения вопроса;
- без markdown, без списков, без оценки в тексте (оценка только в score).

Правила интерпретации score:
0–2 — ответ неверный, не по теме или понимание отсутствует
3–4 — слабое понимание, существенные пробелы или ошибки
5–6 — частично правильный ответ, базовое понимание
7–8 — хороший профессиональный ответ
9–10 — глубокое понимание, уверенный экспертный уровень

Если по смыслу ответ кандидата совпадает с эталоном (те же типы, операции, функции с учётом ASR-искажений написания) — ставь 8–10, не 7–8 из-за формы слов в транскрипте.
```

## Сообщение 2: `role: user`

Шаблон (`build_evaluation_user_message`):

```
Входные данные:

[ВАКАНСИЯ]
{vacancy_text}

[ВОПРОС]
{question}

[ЭТАЛОННЫЙ ОТВЕТ]
{reference_answer}

[ОТВЕТ КАНДИДАТА — расшифровка ASR, не дословная цитата]
{candidate_answer}

Перед оценкой: выпиши для себя ключевые термины из эталона и проверь, есть ли в ответе кандидата те же идеи или созвучные/искажённые ASR варианты этих терминов. Ошибки только в написании ASR не штрафуй.
```

### Откуда подставляются переменные

| Переменная | Источник |
|------------|----------|
| `vacancy_text` | `resolve_vacancy_text(scenario)`: поле `vacancy_text` в JSON сценария **или** текст из `data/prepared/vacancies/cleaned/transformer/vacancies_{query}.json` (первая вакансия) + суффикс стажа через `append_experience_to_vacancy_text` |
| `question` | `question` из сценария по `question_id` |
| `reference_answer` | `reference_answer` из сценария по `question_id` |
| `candidate_answer` | поле `text` из `transcript.json` (Whisper ASR) |

Сценарий: `data/interviews/scenarios/{query}.json`, где `query` — slug кампании (например `camp_2`).

[ЭТАЛОННЫЙ ОТВЕТ]
В PHP есть индексные и ассоциативные массивы. Доступ к элементам идёт по индексу или ключу. Часто используют foreach, array_merge, array_filter, count. Нужно понимать разницу между массивом и объектом.

Ассоциативные массивы, они нужны и они являются аналогами объектов в других языках, то есть есть какой-то ключ и есть значение. Индексовые массивы доступ к информации осуществляется по индексу.

## Ожидаемый ответ модели

Модель должна вернуть **только JSON** (парсится в `_parse_json_from_llm`):

```json
{
  "score": 8,
  "feedback": "Краткий отзыв на русском, 1–2 предложения."
}
```

После парсинга в `evaluation.json` дополнительно сохраняются служебные поля (не часть промпта):

```json
{
  "question_id": "q_arrays",
  "question": "...",
  "score": 8,
  "feedback": "...",
  "model": "llama-3.3-70b-versatile"
}
```

## Когда вызывается

1. После завершения интервью кандидатом (`POST .../complete`) — фоновая задача `process_interview_background`.
2. При пересчёте HR (`POST .../reprocess`) — `run_interview_reprocess_from_video`.
3. На каждый вопрос сценария — **отдельный** вызов Groq (свой system + user).

Оценка **не** выполняется сразу после загрузки видео: при upload только ASR (`skip_evaluate=True`).
