# Инструкция агента: AI Resume Screening

## Контекст проекта

Репозиторий — часть **магистерской диссертации**.

**Тема:** «Применение нейросетевых моделей для создания системы автоматического скрининга кандидатов».

**Цель работы:** разработка многоэтапной системы автоматического скрининга кандидатов.

### Этапы системы (общая архитектура)

1. **Сопоставление резюме и вакансии (Resume–Vacancy Matching)** ← текущий этап в этом репозитории  
2. Оценка ответов кандидата на вопросы интервью  
3. Анализ эмоций кандидата во время видео-собеседования  
4. Финальная оценка кандидата  

---

## Текущий этап разработки

В данном репозитории реализуется **только первый этап**: **Resume–Vacancy Matching**.

Это основная ML-задача проекта.

### Постановка задачи

- **Формально:** задача **Learning-to-Rank (LTR)**.  
- **Цель этапа:** для каждой вакансии определить степень соответствия резюме кандидата и сформировать **ранжированный список кандидатов**.

### Требуемые выходы для каждой вакансии

1. **Вычислить** score соответствия для каждого резюме (resume–vacancy relevance score).  
2. **Отсортировать** резюме по этому score (ранжирование).  
3. **Отобрать** наиболее релевантных кандидатов (top‑k или по порогу).

### Ожидания от агента

- Предлагать и реализовывать решения в рамках **Learning-to-Rank** (метрики ранжирования, loss-функции, подходы: pointwise/pairwise/listwise при необходимости).  
- Учитывать, что данные и пайплайн (сбор резюме/вакансий, предобработка, эмбеддинги и т.д.) должны служить задаче ранжирования и отбора кандидатов по вакансии.  
- Не смешивать с этапами 2–4: в этом репозитории фокус только на сопоставлении резюме–вакансия и ранжировании.

## Структура репозитория (кратко)

- `main.py` — точка входа (сбор/подготовка данных, пайплайн).  
- `services/` — сервисы: работа с API (hh_auth, hh_fetch_*), предобработка (clean_text, normalization), анализ и ранжирование (analysis/, bm25, эмбеддинги: minilm, e5, ru-sbert и др.).  
- `data/` — сырые и подготовленные данные (резюме, вакансии).  

При добавлении кода сохраняй разделение: загрузка/нормализация данных → эмбеддинги/ранжирование → оценка и отбор кандидатов.
